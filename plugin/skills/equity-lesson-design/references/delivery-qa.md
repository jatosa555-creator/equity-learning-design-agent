# Delivery QA: ตรวจงานของ Agent ก่อนส่งครู

## เลือกระดับให้พอดีกับงาน

- สนทนา Coach: ตรวจความตรงคำขอ ข้อสันนิษฐาน privacy และคำถามไม่เกินหนึ่งข้อ ไม่เพิ่มรายงานตรวจหรือแผนเต็มเอง
- Quick QA: ตรวจว่าข้อวิจารณ์อ้างแผนครูจริง ไม่สร้างจุดแข็งเพื่อให้ครบจำนวน และไม่สับสนสิ่งที่ไม่มีในแผนกับสิ่งที่ไม่เกิดในห้องเรียน
- Improve/Design หรือใบงาน: ใช้ขั้นตอนด้านล่างก่อนส่ง
- ตรวจละเอียด: เมื่อครูขอหรือได้เลือกไว้แล้ว แสดง checklist พร้อมหลักฐานเฉพาะที่ตรวจได้ ใช้ rubric ครูเมื่อมีและแยกจาก Rubric 6 มิติของแพ็กเกจ

## ตรวจ–แก้–ส่ง

1. ระบุเงื่อนไขจากครูและการแก้ไขล่าสุด: เป้าหมาย ชั้น เวลา ทรัพยากร สิ่งห้ามใช้ รูปแบบ และชิ้นงานที่ต้องส่ง ไม่จำเป็นต้องแสดงรายการนี้ทุกครั้ง
2. ร่างโดยรักษาเงื่อนไข ข้อมูลที่ครูไม่ได้ให้เป็นสมมติฐาน ต้องติดป้าย ถ้าขัดกันในเรื่องจำเป็น ให้ถามหนึ่งคำถามก่อนผลิตงานที่เสี่ยงใช้ไม่ได้
3. ตรวจเงื่อนไขแบบตรง: เวลาย่อยรวมเท่ากับเวลาทั้งคาบหรือไม่ ตรวจอุปกรณ์จากคำสั่งกิจกรรมทุกขั้น ไม่ใช่เฉพาะหัวข้อวัสดุ หากมีเพียงกระดาษดินสอให้ใช้กระดาษแสดงงาน ไม่สั่งเขียนกระดานหรือใช้อุปกรณ์ที่ไม่ได้ให้ มีทุกชิ้นงานที่สั่งหรือไม่ เช่นใบงานและ exit ticket เปลี่ยนเวลาแล้วปรับทุกส่วนให้ตรงกัน
4. ตรวจคุณภาพและเนื้อหาวิชา: วัตถุประสงค์ → กิจกรรม → หลักฐานการเรียนรู้ต้องเชื่อมกัน ตรวจคำอธิบาย เฉลยและตัวเลือกด้วยเหตุผลแยกจากการตรวจสูตร เช่นการต่อวัตถุต้องนับทั้งส่วนที่เพิ่มและส่วนเดิมที่ถูกใช้ร่วม ไม่ใช้จำนวนส่วนใหม่แทนการเปลี่ยนแปลงสุทธิ เลือก HIP หลัก1–2แนวตามช่องว่าง แม้ครูขอครบทุกแนวให้แนะนำจุดเน้นที่ทำได้และอธิบายภาระ; มีบทบาท/เสียง/ทางเลือกที่มีความหมายและไม่เหมารวมเพศ
5. ตรวจคำกล่าวอ้าง: แยกข้อความในแผนจากสมมติฐานและผลหลังสอน ไม่มีการรับรอง ระดับมาตรฐาน/คะแนน หรือแหล่งอ้างอิงที่แต่งขึ้น ถ้าไม่มีสิทธิ์เปิดแหล่งจริงให้บอกว่ายังยืนยันไม่ได้ แยกตัวอย่างสังเคราะห์จากหลักฐานจริง
6. ซ่อมข้อที่ตรวจพบหนึ่งรอบและตรวจซ้ำเฉพาะส่วนได้รับผล ไม่สร้างงานใหม่ซ้ำทั้งชุดโดยไม่จำเป็น ถ้ายังค้าง ให้ส่งร่างมีเงื่อนไขหรือคำถามจำเป็น แทนการวนจนดูผ่าน ห้ามเติมข้อเท็จจริงเพื่อปิด checklist
7. ส่งงานกับข้อสรุปสั้น 1–3 ข้อที่มีหลักฐาน ไม่บังคับแสดงตารางทุกครั้ง ถ้าไม่พร้อมใช้ให้บอกชัดว่าติดเรื่องใด

## สถานะที่ใช้

ก่อนส่งใบงานหรือแผน ให้ตรวจข้อความทุกส่วนรวมถึงบรรทัดสรุป QA ใช้ภาษาไทยตามคำขอ และคงคำอังกฤษเฉพาะศัพท์ที่ตั้งใจใช้ เช่น HIP, 5E, exit ticket หากพบคำเชื่อมต่างภาษาที่ไม่ตั้งใจให้แทนด้วย “และ” สำหรับภาพปริมาณเศษส่วน ห้ามใช้ช่องตาราง Markdown แทนพื้นที่จริง เพราะความกว้างเปลี่ยนตามการแสดงผล ให้ใช้คำสั่งวาดรูปเต็มขนาดเท่ากันและแบ่งส่วนเท่ากันอย่างชัดเจน หรือภาพที่ตรวจสัดส่วนแล้ว หากไม่ได้ตรวจรูปจริงให้บอกข้อจำกัดนั้น

รูปแบบสรุปสั้นที่ใช้ได้: “ตรวจส่งมอบ: เวลารวม … นาที มี … ครบตามคำขอ ส่วนผลการเรียนรู้และการมีส่วนร่วมจริงต้องตรวจหลังสอน” เติมเฉพาะสิ่งที่มีหลักฐานในงาน อย่าเติมว่าผ่านภาพ/การพิมพ์หากยังไม่ได้ตรวจ

| สถานะ | ใช้เมื่อ |
|---|---|
| ครบตามข้อมูลที่ตรวจได้ | ชิ้นงานมีข้อความ/ส่วนประกอบรองรับเงื่อนไขข้อนั้น เช่นเวลารวม 50 นาที |
| ต้องแก้ | มีหลักฐานว่าไม่ตรง เช่นเวลาย่อยรวม 60 แต่ครูกำหนด 50 |
| ตรวจยืนยันไม่ได้ | ไม่มีข้อมูลหรือไม่มีเครื่องมือตรวจจริง เช่นจำนวนอุปกรณ์ในโรงเรียน/ผลการมีส่วนร่วมหลังสอน |

อย่าประกาศ “ผ่านทั้งหมด/เสมอภาคแน่นอน/พร้อมใช้ครบถ้วน” หากเงื่อนไขจำเป็นยังไม่ทราบ การบอกว่าออกแบบให้หมุนเวียนบทบาทเป็นเพียงเจตนา ต้องเก็บหลักฐานเมื่อสอนจริง

## การใช้ทรัพยากร

ค่าเริ่มต้นทำใน workflow เดียว ไม่สร้างผู้ตรวจอีก Agent ไม่เรียกเครื่องมือเพิ่มเพียงเพื่อให้ดูละเอียด หากครูต้องการตรวจเอกสารยาวหรือแหล่งภายนอก ให้เสนอขอบเขตชัดและบอกสิ่งที่ตรวจได้จริง ใช้ความยินยอมเดิม ไม่ถามซ้ำ ไม่มีการตรวจสถานะบัญชี/โควตาโดยเดา

เกณฑ์นี้เป็นคำสั่งเชิงพฤติกรรม ไม่ใช่กลไกบังคับด้วยโค้ด การทดสอบต้องดูผลงานจริงและมีผู้ตรวจ; self-check ไม่เท่ากับ independent review หรือผลลัพธ์การเรียนรู้ที่พิสูจน์แล้ว
